## Why publish v0.1 with known gaps

Honest framing up front: v0.1 has documented gaps (no Python scanner, no dotenv fallback, no multi-component handling — see `docs/v0.2-plan.md`). Three of five projects in the author's own workspace produce empty or wrong manifests on v0.1.

Why ship anyway:

1. **External dogfood loop.** Until v0.1 is on npm, nobody outside this workspace can try it. No external try → no external bug reports → v0.2 priorities are author opinion.
2. **JS/TS-first is consistent with adoption math.** AI-assisted dev tooling adopts in the JS ecosystem first. Shipping the JS path that works is a real product.
3. **Publishing forces the boring work.** `LICENSE` files, `package.json` description fields, README scope statements — all visible-to-others-only, all easy to skip if you never publish.
4. **Documented gaps are a feature, not a bug.** The "known gaps" release note is a credibility move: "we know what doesn't work, here's the timeline" beats "looks shiny, breaks immediately on Python."

## Known gaps

This is v0.1. We dogfooded against five real projects and the gaps below are real.

- **No Python scanner.** Three of five test projects in the author's workspace are Python-primary and produce empty or near-empty manifests. **v0.2 ships Python (stdlib, pydantic-settings, django-environ).**
- **No dotenv fallback for empty scans.** When the scanner finds 0 references but `.env*` files exist, `init` produces an empty manifest instead of drafting from the `.env`. **v0.2 fixes this.**
- **Multi-component repos get mashed.** A monorepo with several Python+TS+Rust projects gets a single root manifest that doesn't match any individual `.env`. **v0.2 introduces `workspace.yml`.**
- **No cloud adapters.** Cloud-aware features (provider drift detection, L2 signed seals) are Phase 2, paid.
- **JS/TS scanner doesn't see `defineEnv({ required: [...] })` array literals.** When you list resource names as data inside the runtime loader's required-array, the scanner doesn't see them as references. Use `envmanifest generate-types` for code-side detection. Documented in `examples/node-cli`.

The full v0.2 plan: [docs/v0.2-plan.md](https://github.com/adam-scott-thomas/envmanifest/blob/main/docs/v0.2-plan.md).

## License

MIT for OSS components (CLI, runtime, MCP local, schema). Cloud adapters when they ship will be BSL 1.1 → Apache 2.0 after 2 years.
```
